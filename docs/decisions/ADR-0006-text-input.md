# ADR-0006: 文字输入路线（Text Input）

- 编号：ADR-0006
- 日期：2026-10-22
- 状态：accepted (code stage) —— 起点路线已采纳；补齐真实文字输入为条件性动作，真机输入验收 **UNVERIFIED**
- 关联需求：PRD §2.1 E02、§3.1 FR04、§4.2「输入」行、§5.2 用例 7、§6 M12、§5.1 UniPadNotes.ipa 文本保存用例
- 关联契约：`config/machine.json` `devices.input`（`keyboard: pending`）、`unipad.errors.ErrorCode.INPUT_FAILED`

## Context

1. PRD §2.1 E02 记录上游自述「文字键盘仍未完成」（作者自述、未独立复现）。因此不能假定客体已具备可用的硬件键盘通道。
2. FR04 要求「显示、单点触摸、Home、基础文字输入」，并明确**文字输入可先使用客体屏幕键盘；如果不可用，则需补齐实际文字输入**。MVP **不要求中文输入法、组合键和多点触控**。
3. PRD §4.2 输入行策略是「复用 VirtIO tablet/Home，再补文字」，前置验证为「坐标缩放、拖动、释放事件与实际文字输入」。`config/machine.json` 中 `devices.input.keyboard` 当前为 `pending`。
4. PRD §5.1 的 UniPadNotes.ipa 用例要求「输入测试文本，保存到应用容器，重启后恢复」，PRD §5.2 用例 7 要求「输入本次生成的字符串并保存」——即**必须有一次可验证的文本录入**，否则 IPA MVP 的数据持久化验收无法进行。
5. 宿主是 Windows 笔记本，物理键盘存在；但「宿主收到按键」不等于「客体界面响应」（PRD §6 M12 的「不足以通过的情况」即「宿主窗口收到按键但客体无响应」）。

## Decision

1. **起点：客体屏幕键盘（On-Screen Keyboard）。** 宿主侧先只保证指针/触摸链路（VirtIO tablet：坐标缩放、按下、拖动、释放）与 Home 事件可靠，文字录入通过点击客体屏幕键盘完成。宿主**不**先实现 virtio-keyboard 文本通道。
2. **条件性补齐：仅当屏幕键盘不可用时，才补齐真实文字输入。** 「不可用」的判定必须是可复现的证据，而不是主观感受，判据包括：屏幕键盘无法唤出、按键无可见反馈、或输入延迟使 UniPadNotes 文本用例无法在合理时间内完成。判定过程与结论记入实验记录。
3. **补齐时的最小范围**：宿主键盘事件 → 客体可见响应（文本出现在目标输入框），含 ASCII 可打印字符、退格、回车；仅此而已。**中文输入法、组合键（chords）、多点触控明确排除在 MVP 之外**（PRD §3.1 FR04）。
4. **输入失败必须归类为 `INPUT_FAILED`**，并在证据中同时保留「宿主发送事件的时间戳」与「客体对应帧改变的时间戳」，用于 PRD §5.3 的点击响应 p95 指标。宿主窗口收到按键但客体无响应 → 判失败，不得判通过。
5. **宿主侧窗口定位按 QEMU 窗口标题/PID**，不按显示适配器（`host-inventory.json` 记录本机有多个虚拟显示适配器，会干扰枚举）。

## Consequences

**正面**

- MVP 初期的宿主输入适配面最小（指针 + Home），可在代码阶段用 fake 输入链路完整测试坐标缩放与事件序列。
- 若屏幕键盘可用，则完全规避上游未完成的键盘工作，IPA MVP 不必等待键盘通道。
- 「补齐」被设为有条件、有判据的动作，避免范围悄悄膨胀到 IME/组合键/多触控。

**负面 / 代价**

- 屏幕键盘输入速度慢、易错，会影响 UniPadNotes 文本用例与交互性能指标；若因此超时，只能记为限制，不得删掉用例。
- 若屏幕键盘不可用，需要新增客体键盘通道适配，工作量与风险当前**无法估算**（无上游证据），属潜在阻塞项。
- 排除中文 IME 意味着含中文输入的 App 兼容性无法验收；应用支持矩阵中必须如实记录该限制（PRD §10：支持矩阵按「某个包版本 + 某个系统构建 + 某个运行配置」记录）。

**不做的事**

- 不把「宿主键盘事件已发送」当作输入成功。
- 不在 MVP 内承诺中文输入法、组合键、多点触控。
- 不用预置文本文件代替运行时输入来通过 UniPadNotes 用例。

## Status

accepted (code stage)。代码阶段可完成：指针/触摸事件序列与坐标缩放模型、Home 事件、`keyboard: pending` 的配置占位与显式开启开关、输入证据（时间戳对）采集、`INPUT_FAILED` 分类。**屏幕键盘可用性判定与 M12 交互验收未执行，标记 UNVERIFIED / BLOCKED（无真实客体）**。

## Evidence-required

| 项 | 证据 |
| --- | --- |
| 指针/触摸 | 宿主发送坐标 → 客体界面变化的带时间戳截图对；拖动与释放事件序列 |
| Home | Home 事件 → 客体回到 SpringBoard 的画面证据 |
| 屏幕键盘（起点） | 唤出、按键可见反馈、目标输入框出现预期字符 |
| 文本用例 | UniPadNotes：输入本次生成的字符串 → 保存 → 关闭重开 App 可读（PRD §5.2 用例 7） |
| 若补齐键盘 | 判定「屏幕键盘不可用」的证据、新增通道的实际参数、ASCII/退格/回车逐项结果 |
| 性能 | 20 次交互的 p95 ≤ 2s（初始目标，PRD §5.3），保留宿主发送与帧改变的时间戳 |
