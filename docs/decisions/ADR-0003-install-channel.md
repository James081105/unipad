# ADR-0003: IPA 安装通道（Install Channel）

- 编号：ADR-0003
- 日期：2026-10-22
- 状态：**proposed** —— 协议先行已采纳；具体通道选择推迟到 M10 实验，真机安装验证 **UNVERIFIED**
- 关联需求：PRD §2.3 H03、§3.1 FR06、§5.1、§5.2 用例 3–4/10、§6 M10/M10a、§9.1 安装接口契约、§10
- 关联契约：`unipad.models.InstallResult`、`unipad.guest.protocol`、`unipad.errors.ErrorCode.{TRANSFER_FAILED, SIGNATURE_OR_POLICY_REJECTED, INSTALL_SERVICE_UNAVAILABLE, REGISTRATION_FAILED, MISSING_DEPENDENCY, DYLD_FAILED}`

## Context

1. PRD §10 列出 IPA 安装链的七个子问题（包预检、主客体传输、签名与信任、安装服务/辅助器、动态加载、图形与输入、持久化），并明确**候选安装通道可以是客体安装服务、受控辅助器或经验证的离线/重启辅助方式**——即通道本身尚未确定。
2. PRD §4.1 组件职责对「IPA 适配层」的初始选择是「接口先固定，具体客体安装通道由实验选择」。
3. 上游对 iPadOS 在 QEMU 下的安装能力**没有**可供本机直接引用的证据；PRD §2.3 H03 只假设「客体可接受自有测试 App 的安装和执行」，最小验证是「同一 IPA 经真实安装、注册和信任链进入 SpringBoard」。
4. FR06 要求**运行时导入**：桌面启动后选择一个此前未安装的 IPA，完成检查、传输、安装、注册和状态反馈；且明确「导入新 App 不应要求重新编译 XNU 或重新生成整套系统镜像」。
5. 存在一条容易误判为达标的捷径：把 `.app` 预置进 Data seed / 镜像。PRD §10 末句与 §3.1 FR06 都明确 **只修改 Data seed 的预装方案不通过 FR06**。

## Decision

1. **先定协议，后选通道**：代码阶段首先固定宿主↔客体协议（`unipad.guest.protocol`：消息类型、字段、版本协商、错误码映射、幂等与重传语义、能力查询），使三种候选通道——(a) 客体安装服务、(b) 受控辅助器、(c) 经验证的离线/重启辅助方式——可以**复用同一协议与同一套宿主侧状态机**。通道差异被限制在传输层与执行器，不渗透到 CLI 契约。
2. **通道选择推迟到 M10 实验决定**，判据（按优先级）：
   - 能否真正建立应用容器、注册应用与图标（PRD §6 M10 通过证据：新包的安装、信任、注册、图标与记录）；
   - 是否满足 FR06 的「桌面启动后导入此前未安装的 IPA」，且**不要求重编 XNU、不重新生成整套系统镜像**；
   - 是否需要重启客体：若暂时需要重启，必须在产品界面明确显示（PRD §10），并记为降级而非达标；
   - 失败原因是否可归入 PRD §10 的既有故障分类。
3. **安装结果永远按阶段上报，不按意图上报**：`InstallResult.stage` 取 `received|checked|transferred|installed|registered|failed`。**文件传输成功不得返回 `installed`**（PRD §9.1）；只有客体确认容器/注册/图标后才是 `registered`。信任方式（`trust_mode`）必须被记录，不得假定（PRD §5.1：不能把未签名包、普通开发签名包、客体所有者信任包混为同一支持类别）。
4. **预装仅作诊断**：把 `.app` 放进 Data seed 只允许作为 M10/M10a 的对照与诊断手段，用于分离「传输问题」与「客体安装/信任问题」；**任何以预装图标通过 FR06 的宣称都无效**（PRD §3.1、§10、附录 A 禁止事项）。
5. **签名与信任单独立项（M10a）**：自有测试 App 的签名方式、客体信任策略、权限与失败原因必须可追踪；「无 DRM」不等于「允许执行」（PRD §2.2-3、§6 M10a）。

## Consequences

**正面**

- 宿主侧 CLI 契约（`unipad install <ipa>` 返回包哈希、bundle ID、当前阶段、信任方式、错误类型、日志位置）在通道未定前即可实现与测试，WP 之间不必互相等待。
- 三种通道可并行实验，失败可按 PRD §10 的子问题分类定位，不必整体重来。
- Fake 安装服务可在代码阶段驱动完整状态机与故障注入，不依赖真实客体。

**负面 / 代价**

- 协议是**推测的接口**：PRD §2.3 H06 已警告「不先假定 API 格式兼容」。若客体侧真实接口与协议假设不符，协议需要修订，修订必须作为独立决策记录，不得随功能修改偷偷放宽。
- 通道未定前，`INSTALL_SERVICE_UNAVAILABLE` / `REGISTRATION_FAILED` 只能算分类就绪，不能算已支持。
- 若最终只剩「重启辅助」通道可用，产品必须显式呈现重启步骤，FR06 的验收措辞需要单独说明（属于验收条件变更，需记录证据与影响）。

**不做的事**

- 不把复制文件、解压 `.app`、出现图标当作安装完成。
- 不在没有客体信任证据的情况下宣称「签名合规」。
- 不因通道实验困难就把 FR06 悄悄改成「预装即可」。

## Status

proposed。代码阶段交付：`unipad.guest.protocol` 消息与版本协商模型、安装状态机与阶段语义、`InstallResult` 契约、Fake 安装服务与故障注入。**通道选择与 M10/M10a 现场验证未执行，标记 UNVERIFIED / BLOCKED（无真实客体安装服务）**。

## Evidence-required

M10 / M10a 通过必须留存：

| 证据 | 说明 |
| --- | --- |
| 输入包 SHA-256 | PRD §5.2 用例 3 要求记录；并先证明该包此前未安装 |
| 包预检报告 | Device 平台、ARM64 slice、最低系统版本、加密信息、包结构（`Payload/*.app`、Info.plist、主可执行文件、Mach-O、动态库） |
| 传输完整性 | 客体侧收到包的哈希与宿主侧一致 |
| 信任证据 | 所采用的签名/信任方式、客体侧接受或拒绝的原始反馈 |
| 安装/注册证据 | 应用容器建立、注册记录、SpringBoard 真实图标 |
| 安装接口返回 | `InstallResult` 完整字段（含 `stage`、`trust_mode`、`log_path`） |
| 通道与配置记录 | 实际使用的通道、是否需要重启、系统构建号（关联 ADR-0001） |
| 失败样本 | PRD §5.2 用例 10：导入不支持的平台包，返回明确原因且系统保持可恢复 |
